# Terraform AWS Serverless Contact API

A serverless contact API built on AWS and provisioned entirely with Terraform.

This project demonstrates how to build and deploy a simple serverless backend using Amazon API Gateway, AWS Lambda, Amazon DynamoDB, and IAM.

No AWS infrastructure was manually created through the AWS Management Console.

---

## Overview

The API accepts contact form submissions through an HTTP endpoint and stores the submitted information in DynamoDB.

The infrastructure is managed as Code using Terraform.

A typical request flows through the following architecture:

Client
  |
  v
Amazon API Gateway
  |
  v
AWS Lambda
  |
  v
Amazon DynamoDB

---

## Architecture

### Request Flow

1. A client sends a `POST` request to `/contact`.
2. Amazon API Gateway receives the request.
3. API Gateway invokes the Lambda function.
4. Lambda parses the JSON request body.
5. Lambda generates a unique UUID for the submission.
6. Lambda stores the contact information in DynamoDB.
7. Lambda returns a success response to the client.

---

## AWS Services

### Amazon API Gateway

Provides the public HTTP endpoint:

`POST /contact`

### AWS Lambda

Runs the Python 3.13 backend logic without requiring a server.

### Amazon DynamoDB

Stores contact submissions using a unique UUID as the partition key.

The table uses on-demand billing with `PAY_PER_REQUEST`.

### AWS IAM

Provides Lambda with only the permissions required to write contact submissions to the DynamoDB table.

### Terraform

Terraform provisions and manages the entire AWS infrastructure.

## Infrastructure

Terraform creates:

- DynamoDB table
- Lambda execution IAM role
- Lambda IAM policy
- Lambda function
- API Gateway HTTP API
- API Gateway Lambda integration
- API Gateway route
- API Gateway stage
- Lambda invocation permission
